## Linux Troubleshooting Lab
Практическая лаборатория по диагностике и устранению неисправностей в Linux.

Репозиторий содержит намеренно сломанные сценарии, которые имитируют реальные проблемы: сеть, DNS, диски, сервисы, права доступа, процессы и другие типовые инциденты. Цель — тренировать навыки troubleshooting в контролируемой среде.


> Важно: лабораторные работы изменяют настройки системы. Запускайте их только в виртуальной машине или на тестовом хосте. Не используйте на рабочей или production-системе.

### Что внутри
* Готовые лабораторные сценарии в каталоге labs/.
* Автоматический запуск «поломки» и сброс состояния.
* Система подсказок с тремя уровнями.
* Проверка решения одной командой.
* Подробные разборы решений и теоретические материалы.
* Vagrantfile для быстрого поднятия изолированной VM.

### Требования
* Linux-система с systemd:
* Ubuntu 22.04+
* Debian 12+
* Fedora
* Arch Linux
* Права root или sudo.
* Bash 4+.
* Базовые утилиты: ip, systemctl, curl, df, ps, ping.
* Для DNS-лабы могут понадобиться dig, getent, resolvectl, tcpdump.

Если dig отсутствует:

```
bash

# Debian/Ubuntu
sudo apt install dnsutils

# Fedora/RHEL
sudo dnf install bind-utils
```

### Быстрый старт
```
bash
# Клонируем репозиторий
git clone https://github.com/YOUR_USERNAME/linux-troubleshooting-lab.git
cd linux-troubleshooting-lab

# Делаем CLI-скрипт исполняемым

./scripts/lab.sh list
```

### Вариант через Vagrant
Если не хотите запускать лабы на основном хосте:

```
bash
vagrant up

```

### Как пользоваться

```
bash
# Запустить лабораторию — система будет приведена в сломанное состояние
sudo ./scripts/lab.sh start 01-network-dns

# Получить подсказку. Уровни: 1, 2, 3
./scripts/lab.sh hint 01-network-dns 1

# Проверить, решена ли проблема
sudo ./scripts/lab.sh check 01-network-dns

# Сбросить лабораторию в исходное сломанное состояние
sudo ./scripts/lab.sh reset 01-network-dns

```

Типовой цикл прохождения:

1. Запустить лабу.

2. Прочитать labs/<id>/README.md.

3. Провести диагностику самостоятельно.

4. При необходимости открыть подсказки.

5. Исправить проблему.

6. Выполнить check.

7. Сбросить лабу перед переходом к следующей или перед повторным прохождением.

### Команды CLI
|Команда|Назначение|
|---|---|
|./scripts/lab.sh list|Показать доступные лаборатории|
|sudo ./scripts/lab.sh start <id>|Запустить лабораторию и сломать систему|
|./scripts/lab.sh hint <id> <level>|Показать подсказку уровня 1–3|
|sudo ./scripts/lab.sh check <id>|Проверить, устранена ли проблема|

### Как добавить новую лабораторию

Создайте каталог labs/<id>/ со следующими файлами:

```
text
labs/<id>/
├── README.md
├── break.sh
├── check.sh
├── hints.md
├── solution.md
└── theory.md
```

**break.sh** — приводит систему в сломанное состояние.

**check.sh** — возвращает успешный код, если проблема решена.

**hints.md** — три уровня подсказок.

**solution.md** — пошаговое решение.

**theory.md** — теория по теме.

**README.md** — сценарий, симптомы и ожидаемый результат.

После добавления каталога лаборатория должна появиться в ./scripts/lab.sh list.

### Безопасность и ограничения
- Лабы могут менять /etc/resolv.conf, настройки сети, systemd-сервисы, firewall и другие системные параметры.

- Перед запуском рекомендуется сделать snapshot VM.

- Если состояние системы стало неожиданным, используйте reset для текущей лабы.

- Не запускайте скрипты на хостах, где важна стабильность сетевых настроек.

- Некоторые сценарии могут временно нарушить доступ в интернет — это ожидаемо.

### Диагностика проблем с самой лабораторией
```
bash
# Проверить список лаб
./scripts/lab.sh list

# Посмотреть, что делает запуск
sudo bash -x ./scripts/lab.sh start 01-network-dns

# Проверить статус проверки
sudo ./scripts/lab.sh check 01-network-dns
```

Если лаба не запускается, проверьте:

запущены ли вы с sudo;

существует ли каталог labs/<id>;

исполняемые ли скрипты break.sh и check.sh;

не заблокированы ли нужные системные файлы.
